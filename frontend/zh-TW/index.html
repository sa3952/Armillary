在計算頁選「古典完整」，星盤算完會接著排出時間主星；選「自訂」，在結果的「時間主星」一章按一下排出。規則與出處見〈年度時間主星的規則與出處〉，入門見〈年度時間主星入門〉。只想排其中一種：線上計算年度小限與年主星、線上排法達時間主星、黃道釋放計算、十年期時間主星計算。

FIG 1.1 — 同一顆星，三種說法

黃道、赤道、地平——
為什麼要三套？

黃道座標問「它在十二宮的哪裡」，赤道座標問「它在天球的哪裡」，地平座標問「此時此地你要抬頭往哪看」。三者互相可換算，但用途完全不同。渾儀一次全給你——不必為了查赤緯或方位角，換一個工具、把生辰再填一次。

  • 黃道環 Ecliptic太陽視行的大圓。傾角 ε＝23°26′31.79″，取這一刻的真黃赤交角（平值加章動），不是固定值。
  • 赤道環 Æquator地球自轉的投影。赤緯由此量起；換一套黃道的算法，赤緯也不會動。
  • 極軸 Axis指向天極。地方恆星時決定它此刻轉到哪裡。
  • 地平環 Horizon觀測地決定的圈。方位角與高度自此量起。
  • 子午環 Meridian上中天所在。中天 MC 即黃道與此環之交。

FIG 1.2 — 同一時刻，兩種黃道，上升星座不同

兩個網站算出不一樣的
上升星座，誰錯了？

多半是輸入不同，不是誰算錯。先對照兩邊的時區、夏令時間、出生地座標與出生時間；這四樣都一樣還是不同，常見原因是黃道的起算點：回歸黃道從春分點起算，恆星黃道扣掉歲差、從恆星背景起算。同一個上升點，在兩套裡讀出來的星座可以不一樣——下面就是。

回歸黃道tropical 上升 ASC　天秤 1°35′32.3″ 從春分點起算。這是多數西洋占星軟體的預設。
恆星黃道sidereal 上升 ASC　處女 6°58′59.9″ 扣掉歲差 24°36′32.4″（Fagan–Bradley）。上升星座因此退到前一個星座。

兩個都對，差的是起算點，不是天空。但如果一張盤沒寫它用了哪一套，你就沒辦法拿它跟另一張盤對照，也沒辦法重現自己這一張。渾儀把用了哪一套寫在每一次計算的結果與匯出檔裡；想換另一套，在計算頁換一個選項就行。

出生資料，不是秘密儀式。
它只是計算的輸入。

所以我們不保管它。以下是機制，不是承諾——每一條都能在〈安全〉看到它由哪一層執行、涵蓋到哪裡。

  1. 沒有可以存出生資料的地方 不是「我們選擇不存」，是沒有那個元件：沒有帳號資料庫、沒有命盤資料庫、沒有工作階段儲存、沒有請求快取、沒有出生資料快取、沒有背景佇列。
  2. 計算路徑不主動寫磁碟 請求內容 → 請求範圍的資料模型 → 行程鎖底下的同步計算 → 回應與計算卷宗 → 你的瀏覽器記憶體。只有在你按下時，才進剪貼簿或下載檔案。
  3. 計算請求期間寫檔會讓測試失敗 自動化測試在一次預設計算請求期間，攔截 Python 的檔案寫入介面（open、io.open、os.open）；只要出現一次帶寫入旗標的呼叫，測試就失敗。原生函式庫與其他請求組合不在這個測試的涵蓋範圍內。
  4. 日誌只有 11 個固定欄位 每完成一個 API 請求輸出一行事件（網頁與靜態檔不記，伺服器出錯時才記），欄位是封閉清單。不含出生資料、IP、User-Agent、請求內容。這一行會留在容器日誌裡，保存方式見〈隱私政策〉。
  5. 不引入第三方追蹤、分析或遠端日誌相依 不使用追蹤器、廣告、分析或遠端日誌；主機、DNS 與網域在同一家瑞士供應商，那一層的界線寫在〈信任中心〉。站上只有一個資料庫：內建的地名目錄，以唯讀不可變模式開啟，也不寫入你查詢的字串。

這些不必只聽我們說：〈親手驗證〉教你用瀏覽器內建的開發者工具，自己看算一次盤送出的每一個請求都只到本站。

我們不宣稱的：上面說的是沒有主動寫入，不是安全抹除。計算期間資料存在於記憶體中，之後由執行環境回收；我們不宣稱能從記憶體、swap 或當機傾印中安全抹除任何東西。也沒有第三方安全認證或專業滲透測試。

我們的立場

在一個什麼都要你先註冊、先給生日、先開啟通知的年代，我們選擇反過來：不要帳號，不要你的資料，算完就丟。你的出生時刻只在這一次計算裡存在。這不是隱私功能，這是產品的形狀——我們提供的是計算，你不是產品。
